# 調參指南

預設值只是起點。請在實際的裝置、鏡頭位置、光線和人群情境下收資料再調整。

## 1. 先固定 ROI

讓使用者站在正常的互動位置，拖曳 ROI 框涵蓋所有會正對機器人說話的位置，同時避開走道和背景。旁邊經過的人不進 ROI，是降低誤判最有效的方法。

## 2. 偵測信心 `min_conf`

觀察面板上各 track 的 conf：
- 正常狀態下，正對鏡頭的使用者應該穩定高於 `min_conf`。
- 背光、側臉時如果經常低於門檻，會頻繁進入「不確定」，改用聲音判斷。可以稍微調低，或改善光線和鏡頭角度。

## 3. 身分比對 `cos_match` / `cos_weak`

1. 讓 A 站著 30 秒（左右轉頭、前後移動），記錄面板上的相似度，得到「同一人」的分布。
2. 換 B、C 進來，記錄「不同人」的分布。
3. 把 `cos_match` 設在兩個分布之間，偏向「同一人」分布的低端（寧可多一個 track，也不要把不同人合併）。
4. `cos_weak` 用來處理位置沒變但角度改變的情況，一般設成 `cos_match` 的一半左右。

使用備援 HSV 直方圖時，區分能力很弱，`cos_match` 需要大幅調高，結果也只能參考。

## 4. 防閃爍

- 偵測經常漏一兩張：調高 `absent_frames`。
- 離開判定太慢：調低 `absent_frames`、`empty_timeout`，或提高 `fps`。
- 多人互相遮擋：調高 `grace_seconds`。

## 5. 逾時與判斷優先

- 吵雜環境（電視、多人背景聲）：用 `vision`。聲音只在影像不確定時使用。
- 安靜、鏡頭品質不穩定：用 `balanced`。
- 沒有鏡頭或鏡頭常被擋：用 `audio`。
- `vision` 模式下，如果擔心人站著但已經不理機器人，可以設 `present_max_silence`（例如 120 s）。

## 6. VAD（瀏覽器端）

看麥克風音量條：灰線是噪音底，黃線是說話門檻。安靜時音量應該低於黃線，說話時明顯高於黃線。環境吵就調高 `vad_k` 或 `vad_min`；句子中間常斷就調高 `vad_hang`。

## 7. 效能

看資源監控的各階段延遲 p95。如果 total p95 接近 1000/fps ms，或 dropped 一直增加，就降低 fps，或換用更輕量的模型。SFace embedding 通常是最耗時的階段。

## 建議流程

把每次調好的設定「匯出 JSON」，在檔名註記場景（例如 `lobby-noisy.json`），方便比較和回溯。
