# 隱私

presence-demo 用鏡頭和麥克風觀察人，所以設計上盡量少保存、保存越短越好。這一頁把所有規則整理在一起，能測試的都有測試。

## 預設：什麼都不送出、什麼都不寫入

| 資料 | 處理方式 | 保存 |
|---|---|---|
| 鏡頭畫面 | 在記憶體中解碼、分析後丟掉。從不寫入磁碟，也不回傳。 | 只在處理期間 |
| 臉部 embedding（128 個數字） | 存在追蹤器記憶體中，用來在 session 內認人。 | 到 session ENDED（然後清除） |
| 麥克風聲音 | 預設用瀏覽器 VAD（聲音留在瀏覽器）。用 PureSound 時，區塊在伺服器記憶體中處理。 | 幾秒，在記憶體中 |
| 逐字稿（選用 ASR） | 轉送到瀏覽器，網頁記憶體保留最近 100 句。 | 不在伺服器 |
| 日誌 | 結構化事件，只有計數、分數和時間。從不包含像素、聲音、文字或 key。 | 你設定的日誌檔 |

`tests/test_privacy.py`、`tests/test_audio.py`、`tests/test_recording.py` 會跑完整的 session，確認沒有寫入任何檔案。

## 可以開啟的功能

以下功能都**預設關閉**，必須由部署者開啟。

| 功能 | 改變什麼 | 說明 |
|---|---|---|
| 雲端語音辨識 | session 期間把聲音串流到 AssemblyAI（預設只送說話的區塊）。 | [語音辨識](asr.md) |
| 跨 session 使用者判斷 | 還需要 `reid_consent`。每位使用者一張臉部裁切保存在**伺服器記憶體**，最多 10 分鐘；每次比對送兩張裁切到 re-ID 服務。選用的 112 px 縮圖只送到*這個瀏覽器*。 | [Re-ID](reid.md) |
| 錄音 | 由使用者自己開始。音軌在**瀏覽器**中收集，下載到使用者自己的電腦。伺服器什麼都不寫；影像從不錄製。 | [音訊](audio.md#監聽與錄音) |

如果部署其中任何一項，請告知裝置前的人，依規定取得同意（人臉在許多地區屬於生物特徵資料，例如 GDPR 第 9 條、
台灣個人資料保護法），並確認服務提供者的資料保留政策。

## 機密

- 存取權杖只從環境變數 `PRESENCE_TOKEN` 讀取。
- API key（`ASSEMBLYAI_API_KEY`、`TYPESAFE_API_KEY`）來自環境變數或設定頁的密碼欄位；只存在程序記憶體，從不寫入、記錄或回傳給瀏覽器。
- 日誌會遮蔽名為 `key`、`token`、`secret`、`password`、`authorization` 的欄位，以及網址中的 `token=` / `key=`。
- `PRESENCE_NPU_DELEGATE`（原生函式庫）只能用環境變數設定，不能透過網路設定。

## 網路暴露

沒有設定 `PRESENCE_TOKEN` 時，任何連得到這個 port 的人都能使用 demo。對外開放時請設定權杖並使用 HTTPS。
安全問題的回報方式見 [SECURITY.md](../../SECURITY.md)。
