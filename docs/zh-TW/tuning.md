# 調參指南

預設值只是起點。請在實際的裝置、鏡頭位置、光線和人群下調整。好的循環是：一次改一個地方，看介面幾分鐘，
用描述性的檔名**匯出設定 JSON**（例如 `lobby-noisy.json`），再重複。

## 0. 從預設組合開始

在設定 → 預設組合中選最接近的：「推薦」「低角度鏡頭」「單人」「多人圍觀」「吵雜環境」或「低功耗」。
內容見[設定參數](configuration.md#預設組合)。

## 1. 先固定 ROI

請人站在使用者平常站的位置。拖曳臉部 ROI（青色），涵蓋所有會對著裝置說話的位置，避開走道和背景。
讓路人不進 ROI，是減少錯誤最有效的方法。開啟姿勢時，也一併調整身體 ROI（紫色）。

## 2. 偵測信心 `min_conf`

觀察人員清單中每個 track 的 `conf`。面向鏡頭的使用者應該穩定高於 `min_conf`。如果逆光或側臉常常低於門檻，
系統會一直改用聲音判斷：可以稍微調低，或改善光線和鏡頭角度。

## 3. 身分比對 `cos_match` / `cos_weak`

1. 讓 A 站 30 秒，轉頭、前後移動，記下人員清單中的相似度，這是*同一人*的範圍。
2. 讓 B、C 進來，記下他們的值，這是*不同人*的範圍。
3. 把 `cos_match` 設在兩者之間，偏向*同一人*的低端（寧可多一個 track，也不要把兩個人合併）。
4. `cos_weak` 處理「位置沒變、角度改變」的情況，通常設成 `cos_match` 的一半左右。

## 4. 閃爍與離開

- **Kalman + HMM**（推薦）：主要調 `leave_halflife`。調低 = 更快判定離開；調高 = 更能容忍遮擋。觀察在場機率圖。
- **Rules**：常漏偵測 → 調高 `absent_frames`；離開判定太慢 → 調低 `absent_frames` 或 `empty_timeout`，或提高 fps。
- 多人互相遮擋 → 調高 `grace_seconds`（Kalman 另外調 `coast_seconds`）。

## 5. 誰會加入

`intent_model = score` 時，把滑鼠移到意圖條上可以看到每個線索。旁觀者會加入 → 調高 `w_facing` 或 `join_threshold`；
使用者加入太慢 → 調低 `join_threshold` 或 `intent_tau`。見[互動意圖](intent.md)。

## 6. 判斷優先與逾時

- 吵雜（電視、背景人聲）：`vision`。聲音只在影像不確定時使用。
- 安靜、鏡頭普通：`balanced`。
- 沒有鏡頭或常被擋：`audio`。
- `vision` 模式下，如果「站著但不理裝置」應該結束 session，請設定 `present_max_silence`（例如 120 s）。

## 7. 音訊

- **瀏覽器 VAD**：音量條上的灰線是噪音底，黃線是說話門檻。安靜時應該低於黃線，說話時明顯高於黃線。
  環境吵 → 調高 `vad_k` 或 `vad_min`；句子中間被切斷 → 調高 `vad_hang`。
- **PureSound**：把 `near_range` 設成使用者實際說話的距離（請先開啟並校正距離）。觀察音訊面板的判斷計數：
  沒人時出現很多 `leak` 是正常的（交叉確認正在工作）；`false_reject` 很多代表分離對你的麥克風太激進。

## 8. 效能

看資源面板的各階段 p95 延遲。總 p95 接近 `1000 / fps` ms，或丟棄數一直增加時，請降低 fps 或開啟省電機制。
見[效能](performance.md)。
